# 远端分支静态预检设计经验（2026-08-05）

- 回顾范围：2026-08-04 21:31 至 2026-08-05 21:30（Asia/Shanghai）
- 来源：K1 快速静态预检远端分支支持设计会话
- 类型：AI/LLM 工程经验原始总结

## 1. 审核对象应与用户当前工作区解耦

静态审核可能持续较长时间，要求用户把本地仓库停留在目标分支会阻塞日常开发。更稳妥的方式是把审核对象定义为远端分支解析得到的冻结提交，并在独立缓存中读取对象；用户可以继续切换本地分支或修改工作区，审核结论仍然对应冻结提交。

报告应分别说明两件事：审核工作流自身是否违反只读合同，以及用户工作区在审核期间是否发生变化。远端模式下，后者只做披露，不应自动推翻基于冻结提交得到的结论。

## 2. 远端读取不等于完整克隆

轻量方案只初始化对象缓存，不 checkout 文件，不拉取标签，并优先使用按需对象过滤。每个仓库只获取基线与目标两条引用，三端并行执行且设置独立超时；缓存命中后只增量更新。

仓库中图片、模型和其他大型资源不会因为分支体积大就全部下载。只有证据链直接命中的代码或配置对象才会按需物化，因此实际耗时主要由新增提交、目录树和少量目标文件决定。

## 3. 必须先冻结提交，再开始证据采集

分支是可移动引用。准备阶段应先把远端基线与目标解析为完整提交标识并写入本次运行清单；后续差异、文件读取和报告都只能使用这些冻结标识，不能在不同阶段重新解析分支。

远端不存在、认证失败、网络超时或对象不完整时，该端应标记为无法确认。流程不能静默回退到本地当前分支或新鲜度未知的远端跟踪引用，否则报告看似完成，实际审核对象已经改变。

## 4. 大文件配置只允许在隔离缓存中精确获取

配置工作簿可能由 Git LFS 管理。流程先读取冻结提交中的指针，只在 FunctionPreview 自有缓存中对精确路径执行受限获取，再校验对象标识和大小后交给正式配置读取工具。普通工作区和其他临时目录都不能执行这一步。

这种边界既允许读取实时远端正式配置，又不会在三端正式仓库中产生 fetch、checkout、LFS 下载或工作区改动。

## 5. 设计完成不等于实现完成

本窗口内远端分支预检的设计稿和实施计划已经确认，核心缓存、冻结提交读取和配置物化也进入验证阶段；但真实远端端到端冒烟仍在继续，因此本次只能沉淀已批准的设计模块，不能声称整套功能已经交付。
