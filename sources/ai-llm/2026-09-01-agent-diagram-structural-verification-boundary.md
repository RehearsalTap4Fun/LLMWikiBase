# Agent 架构图工具只能验证结构，不能证明业务理解正确（2026-09-01）

## 背景

Archify 这类工具把“理解仓库”和“绘制图形”拆成两段：Agent 先根据自然语言或源码编写结构化中间表示，工具再负责校验、布局和确定性渲染。它能稳定地产出架构图、流程图、时序图、数据流图和生命周期图，但最终图是否忠于真实业务，仍取决于 Agent 前一段的理解质量。

## 可沉淀经验

### 1. 结构正确不等于语义正确

Schema 校验可以证明节点、连线和字段合法；布局检查可以发现遮挡、越界和可读性问题；确定性渲染可以保证同一输入得到相同结果。这些能力都不能证明组件边界、调用方向和业务责任本身判断正确。交付时应把“工具验证通过”和“架构事实已由项目人员确认”分开描述。

### 2. 结构化中间表示适合纳入版本管理

与直接生成不可编辑图片相比，结构化描述便于审查、差异比较和重复渲染。需求变化时，审查者可以先看节点与关系的差异，再看视觉结果；这也让自动检查聚焦于可机器判断的结构问题，而把业务真实性留给人工复核。

### 3. “单文件交付”不一定等于完全离线

输出虽然可以是独立 HTML，仍要检查字体、图标、更新提示等路径是否访问网络。采用前应在断网环境打开一次，并分别核对默认渲染、可选品牌资源和更新检查，避免把“无需后端服务”误写成“完全无网络依赖”。

### 4. 工程成熟度和业务适用性要分别评估

跨平台测试、持续集成、版本发布和大量测试可以说明工程维护质量较好，但不能替代真实仓库样例验收。最稳妥的采用方式是挑选一份已知正确的系统设计，让工具生成图，再由熟悉项目的人检查组件遗漏、边界误判和异常路径。

## 适用场景

适用于利用 Agent 生成架构图、流程图或技术说明的工作流。核心原则是：机器验证结构与可视化质量，项目人员确认业务语义；两类通过不能互相替代。
