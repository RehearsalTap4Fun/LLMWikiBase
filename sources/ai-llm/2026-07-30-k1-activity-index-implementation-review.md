# K1 活动知识索引落地经验回顾（2026-07-30）

- 回顾范围：2026-07-29 21:30 至 2026-07-30 21:32（Asia/Shanghai）
- 来源：期间内活跃的 Codex 会话与本地交付物
- 类型：AI/LLM 使用经验原始总结

## 1. 轻量索引应保存路由信息，而不是复制全文

本次将 K1 活动远程 Wiki 整理成本地活动目录、主题页和离线查询工具。本地只保存标题、别名、标签、主题摘要、页面树、版本和远程链接；具体规则仍按问题意图实时回源。

这样可以兼顾两件事：模型能够快速定位正确活动和子页面，同时不会因为复制大量正文而形成陈旧的第二份知识库。

## 2. 首次全量同步与后续增量同步要共用同一套校验

同步流程先递归读取完整页面树，再根据页面版本决定是否读取正文。无论首次全量还是后续增量，都必须验证：

- 远程返回数量与实际遍历结果一致，没有分页截断。
- 每个子页面只归属一个一级主题。
- 本地状态、总目录、主题页和子页面表格能逐项对账。
- 失败时目录、主题页和状态文件一起回滚，不留下半套结果。
- 页面移动、改名、暂时无权限或删除都有显式状态迁移规则。

真实同步暴露了多个单元测试难以发现的问题，包括分页接口口径变化、标题尾部特殊空白字符、顶层活动移动后旧页面清理，以及本地目录状态分区与主题 frontmatter 的深度一致性。这说明真实数据 dry-run 和深度校验不可被普通测试替代。

## 3. 人工整理区与自动生成区必须分离

活动摘要、别名和标签需要人工语义判断；页面树、版本和链接更适合自动同步。两类内容如果混在同一区域，增量同步容易覆盖人工判断。

稳定做法是：

1. 自动区每次根据远程元数据重建。
2. 人工区原样保留，并在内容变化较大时重新标记待复核。
3. 首次同步分批复核主题摘要与标签，再用精确的复核标识清理状态。
4. 改名时把旧标题保留为别名，保证历史称呼仍可离线命中。

## 4. 文件写入要采用批量事务

同步可能同时修改总目录、多个主题页和状态文件。逐个覆盖会在中途失败时造成版本错位。本次使用临时输出与原子替换，并通过故障注入验证回滚；对于符号链接、目录联接和异常页面标识则在任何写入前拒绝。

可复用原则：先完整生成和验证一批输出，再一次性提交；删除旧主题页也必须纳入同一个可回滚事务。

## 5. 第三方工具的临时日志也属于凭据与正文泄漏面

真实同步审查发现，上游工具会把远程响应片段写入系统临时日志。即使项目目录本身没有保存正文，也可能通过系统临时目录泄漏内容。

处理方式是删除已确认的敏感日志，并让子进程使用隔离临时目录，随后在 dry-run、正式同步和最终验收中反复确认系统临时日志不再生成。自动化安全检查不能只扫描仓库，还要检查依赖工具的缓存、临时文件和错误输出行为。

## 6. 离线检索需要解释命中原因

查询工具按活动标题、别名、子页面标题、标签和摘要分层打分，并返回命中类型、本地主题页和远程页面。多个候选同分时保留歧义，而不是让模型凭印象选择。

这类索引的核心价值不是全文搜索速度，而是把“为什么命中、下一步应该读哪一页”显式化，为后续回答提供可追溯路由。
