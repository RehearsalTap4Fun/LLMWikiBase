# 读者向传记与生产元数据的分层（2026-08-19）

- 回顾范围：2026-08-18 21:31 至 2026-08-19 21:31（Asia/Shanghai）
- 来源：HistoryImageCreator 批量传记清理会话及产物复核
- 类型：AI/LLM 经验原始总结

## 1. 最终传记只承担面向读者的叙事职责

传记正文应保留标题和生平事迹，不应混入批次定位、资料范围、证据备注、画面说明、造型解释或艺术推测免责声明。这些内容对生产过程有价值，但会破坏读者阅读的连续性，也会让最终产品像内部工作底稿。

“删解释性文本”不等于删除所有限定。史料争议、传统叙事与演义来源等会影响事实准确性的必要限定，应自然写进正文；纯粹用于解释制作过程的内容则应移出。

## 2. 不同信息应进入不同产物

可以把人物包拆成三个职责明确的层次：

- `biography.md`：读者看到的生平正文；
- `data.json`：资料来源、审核状态和生产元数据；
- `prompt.md`：构图、造型、环境光和其他视觉生成说明。

这种分层让每个文件都服务于单一消费者，既保留生产可追溯性，又避免内部说明泄漏到最终阅读体验。

## 3. 人物关系应按叙事价值重写，而不是机械删除

“相关人物脉络”一类备注中可能包含有效历史关系。清理时应判断关系是否直接推动主角生平：直接相关的内容改写进正文，旁支名单和检索备注删除。这样既能去掉资料卡口吻，又不会损失有意义的事迹。

## 4. 批量清理必须同时修正规则源

只改现有传记会让问题在下一批生成时复发。完整闭环包括：

1. 批量清理存量正文；
2. 更新生成规则，明确三类文件的职责；
3. 扫描所有传记中的解释性模板；
4. 验证标题、正文和必要事实限定仍完整；
5. 保留图片、提示词、审核状态等不在本次范围内的成果。

本轮复核确认现有传记均未再命中解释性模板，生成规则也已写明元数据与视觉说明的归属。
