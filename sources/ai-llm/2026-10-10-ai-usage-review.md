# 2026-10-10 AI 使用经验回顾：网关配置、数据分析与前端验证

## 覆盖范围

- **Codex Desktop**：依据公司 Wiki 配置 Claude Code 走 OneHub；保留原配置、收紧权限，并完成鉴权和最小推理验证。
- **Claude Code**：完成大地图 V2 与前后 V1 服务器的留存/付费队列比较及 HTML 报告；修复 Trip 行程展开后目标顶部可能落在视窗外的问题。
- **Cursor**：发现 3 份本地 agent 转录，但文件内没有可验证的 2026-10-10 时间戳，且大量输出为脱敏内容，故不将其作为当天活动证据。

## 有效做法

### 1. 网关或 CLI 配置按“低风险证明链”收尾

配置第三方网关时，先读取官方/内部文档，再检查 CLI 版本和已有配置；变更前备份，只合并必要字段，凭证只判断存在性、不回显。配置文件设为仅当前用户可读写，并清空临时剪贴板内容。

验证分层推进：先验证配置结构与权限，再做不产生推理费用的模型列表/鉴权请求，最后用低成本模型发一条禁用工具、无会话保存、设置超时与预算上限的最小推理请求。这样能区分“网络/鉴权/模型可用”与“CLI 实际推理”两类问题。

### 2. 代理模式与订阅登录模式必须显式二选一

Codex 的流式响应提前关闭，根因不是单纯网络断开，而是网关、令牌类型和模型可用性不匹配。排障时应分别核对：请求是否命中预期 base URL、令牌是否由该网关签发、模型是否在 `/v1/models` 中可用、该模型的流式响应是否含正文。

若改用 ChatGPT 订阅直连，应移除自定义 `openai_base_url` 等代理设置后再重启客户端；不能让 ChatGPT 登录态继续向公司网关发请求。命令行最小对话成功只能证明 CLI 配置已生效，Desktop 仍需完全退出重启以清除缓存。

### 3. 前端交互修复先定位实际渲染分支，再量化验证

“展开后自动定位”的修复中，初始 Playwright 选择器针对的是错误主题分支，导致等待超时。先确认主题/组件选择条件，才能为实际 DOM 选择正确选择器；不要把测试失败直接解释成修复失败。

验收应同时包含行为测量和回归测试：记录展开前后目标元素相对视窗的位置，确认原本在视窗上方的项目被滚回可见区域；随后运行类型检查与测试套件。部署端 HTTP 200 仅说明服务可达，不等同于远端已运行新版本，仍应补充版本或页面内容验证。

### 4. 数据分析提示要把对照、口径与截断条件写进任务

对大地图 V2 的比较使用前后相邻 V1 服务器作对照，固定“首日注册队列、剔除测试号、截至最后完整日”的口径，并按可观测天数排除尚未达到 D6 的服务器。这种把处理组、对照组、观察窗口、指标定义与不完整 cohort 处理写清楚的请求方式，能让结果可复查，也避免把开服时序差异误判为版本效果。

## 失败与调试提醒

- zsh 中 `status` 是保留变量；脚本临时变量使用任务前缀名称，避免请求尚未发出就失败。
- macOS/BSD `sed -i` 与 GNU `sed` 参数不同；自动化编辑前确认平台语法，或使用更可控的补丁方式。
- 浏览器“复制令牌”不一定能从受控剪贴板读回；不要反复尝试提取页面数据。若用户已完成授权，可使用不回显的本地输入/写入流程并立即清理临时介质。

## 可复用检查清单

1. 配置前：备份、确认当前认证模式和目标端点。
2. 配置后：检查权限与占位符，依次做鉴权、模型可用性、最小真实请求。
3. UI 修复后：在真实条件分支中验证，量化可见性，再跑回归。
4. 分析交付前：声明 cohort、对照、截止日、排除规则和无法比较的部分。
