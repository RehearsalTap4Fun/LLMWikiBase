## 1. 从优化清单生成增量策划案

### 推荐流程

1. 先识别链接的真实类型。名称像文档的链接可能实际是在线表格，需要逐个工作表读取。
2. 找到已上线版本的规则或实现作为权威基线。
3. 明确本次是增量案还是完整总案，优先冻结范围再讨论细节。
4. 将清单按功能模块重组，同时保留“原清单—文档章节”映射，兼顾开发拆分与验收追踪。
5. 逐项确认状态、停止条件、异常分支、跨系统关系和兼容策略。
6. 正文和配图完成后，检查每个原始需求是否有唯一落点。

### 为什么按模块组织更合适

按清单逐条写容易把同一状态机拆散；按玩家流程写则不利于开发分工。按功能模块组织，并附清单映射表，能同时保持规则内聚和需求可追踪。

## 2. AI 生成策划配图的边界控制

### 常见失败

- 模型会主动增加看似合理、但未经确认的控件。
- 为了展示多个状态，容易把两个调整点拼进一张图。
- 直接改变画布比例会拉伸原 UI，破坏视觉参考价值。
- 生成稿中的文字和状态可能与正文逐渐分叉。

### 稳定做法

- 使用现有线上界面作为底图和尺寸基线。
- 每张图只解释一个调整点或一个紧密相关的状态组。
- 新控件必须能追溯到已确认需求，发现额外功能立即删除。
- 横版草图需要重新排版为目标比例，不能机械缩放。
- 在最终校验中同时检查图片尺寸、文档引用、关键文案和状态一致性。

## 3. 同步到在线文档的可靠流程

### 写入策略

- 先探测目标链接及其父目录，再创建同级新文档。
- 正文超过单次字符上限时，按完整章节边界拆分追加，不在句子或表格中间硬切。
- 图片作为独立媒体块插入对应图注附近，避免统一堆到文末。
- 写入后重新读取在线文档，核对章节、关键规则、图片块和图文顺序。

### Markdown 转换并非无损

在线编辑器可能重映射标题层级、转义下划线、吞掉花括号占位符或改变表格结构。包含本地化参数、模板变量和类似代码的文本，必须逐项回读。

如果块级修补连续返回同类解析错误，应停止重试并保留明确的人工修正点；反复写入可能损坏整个表格或段落。

## 4. 多代理评审的前置条件

### 冻结同一份评审材料

不同 reviewer 应读取同一版本的原始材料，分别检查需求完整性、正确性、验收标准、可实施性和安全边界。最终由主代理去重、合并和处理冲突，不能把互相转述后的摘要继续传递给下一位 reviewer。

### 派发前检查插件与契约可访问性

本次 Claude 子代理最初找不到评审插件的 reviewer 说明和输出 Schema，导致多个代理先返回“无法按契约输出”，随后才退回自由文本评审。这说明派发前应由主代理先确认：

- 技能路径在当前环境可读。
- reviewer 角色文件存在。
- 输出 Schema 与字段约束已加载。
- 子代理继承了正确的路径或资源标识。

否则并行代理只会并行地产生同一种环境错误。

### 评审结论必须转成可执行修改

“规则不完整”价值有限。高质量 finding 应包含触发场景、矛盾或缺口、业务后果和明确修改要求；验收问题还应落到可观察结果、错误码、数据不变式或并发用例。

## 5. 磁盘与仓库状态是最终证据

- 会话中的“已完成”需要用实际文件、尺寸、提交和仓库状态复核。
- 工作区可能被用户或其他工具切换分支，文件存在性和 Git HEAD 会在排查途中变化。
- 对已提交内容做审计时，优先读取指定 Git 对象，不要为了方便擅自切换用户当前分支。
- 中间状态和最终状态必须分开记录，例如“会话结束时尚未导表”不代表稍后的仓库提交仍未包含导出文件。

## 6. Webhook 与 MCP 凭证安全

本次钉钉机器人测试暴露了三个通用问题：

- 只提供 Webhook Token 时，加签机器人会拒绝请求。
- 当前发送工具未暴露签名密钥、时间戳和签名参数，不能假设可以绕过工具边界自行补齐。
- 新增专用 MCP 配置后，当前会话不会自动热加载；需要重新加载配置或开启新任务，确认工具已经注册后才能调用。

Webhook Token、加签密钥和 MCP URL Key 都属于敏感凭证，不应写入经验文件、日报、自动化记忆或日志。凭证一旦粘贴到对话中，应在完成配置后轮换。本次测试消息没有发送成功。

## 7. 可复用检查清单

1. 链接类型、目录归属和权威基线是否确认。
2. 增量范围是否明确，是否有需求—章节映射。
3. 配图是否只表达已确认需求，并匹配原界面比例。
4. 在线写入是否考虑字符上限、图片位置和 Markdown 转换。
5. 是否完成在线回读，而不是只看接口返回成功。
6. 多代理评审的角色文件和输出契约是否可访问。
7. 结论是否包含触发条件、后果和可执行修改。
8. 最终文件、提交和当前仓库状态是否重新验证。
9. 所有凭证是否被排除，并在暴露后提示轮换。
