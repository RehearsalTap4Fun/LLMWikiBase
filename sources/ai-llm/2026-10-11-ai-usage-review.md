# 2026-10-11 AI 使用经验回顾：结构化委派与证据边界

## 覆盖范围

- **Codex Desktop**：日结自动化在主工作区存在无关脏改动时，使用隔离 worktree 把单个知识库提交变基到远端最新 `master` 后推送。
- **Claude Code**：一段会话把近期 Git 状态和用户消息压缩为待办 JSON；另一段会话按独立维度评估多个应用品类的独立开发可行性。
- **Cursor**：找到 3 份 agent 转录，但文件修改时间均为 6 月、内容无 2026-10-11 的可验证活动时间戳；不纳入当天结论。

## 有效做法

### 1. 把“待办提取”写成受限的信息抽取任务

待办提取提示明确了输入来源（近期提交、工作区状态、AI 会话用户消息）、筛选标准（未完成且值得今天跟进）、字段 schema、最多 8 条和“宁缺毋滥”。输出因此是可直接消费的 JSON 数组，而不是含混的聊天摘要。

可复用模板：先限定证据池，再给出“完成/未完成”的判定标准；为每条结果要求简短标题、难度和来源，并要求没有明确证据时返回空数组。这样能降低模型把已完成工作或推测性事项混入待办的概率。

### 2. 多维评估要显式要求维度独立，并给出评分锚点

应用评估将 `build`（实现难度）、`cost`（边际成本）和 `reach`（获客/冷启动）拆开，要求各自使用 1–5 的锚点且“不要互相传染”。再要求理由指出最致命短板、MVP 工期和严格 JSON 输出，结果适合横向排序或后续程序处理。

对类似市场判断，应把评分当作模型的假设性初筛，而非市场事实：它没有外部竞品、渠道成本、合规或真实 API 报价的实时验证。进入投入决策前，需逐项回查最关键的外部事实。

### 3. 脏工作区的同步操作应隔离，而不是碰触无关修改

知识库提交被本地未暂存的无关文件阻断时，不能为了 `pull --rebase` 暂存、丢弃或改写这些文件。将仅含目标提交的分支放入隔离 worktree，基于远端最新提交重放并推送，可完成同步，同时保留原工作区状态。

操作前后都应检查：原目录的 `git status` 是否未被本任务改变、隔离目录是否只包含目标路径、远端分支是否包含重放后的提交。这个模式尤其适合日常自动化在共享/个人工作区中运行。

## 可复用检查清单

1. 结构化抽取：声明证据范围、排除条件、字段 schema、数量上限和空结果格式。
2. 多维决策：让评分维度独立，提供各档锚点，并单列最关键短板与需回查的外部事实。
3. Git 同步：先区分目标改动与既有脏改动；受阻时用隔离 worktree，不修改用户的未提交内容。
4. 归档依据：只有带可验证活动日期的本地记录才能计入当天覆盖；文件存在或修改时间不能替代会话时间戳。
