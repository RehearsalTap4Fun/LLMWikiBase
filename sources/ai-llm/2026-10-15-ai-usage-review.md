# 2026-10-15 AI 使用经验回顾：先定口径，再报告差异

## 覆盖范围

- **Cursor**：对 KVK 海底赛季参与玩家做当前周期与历史周期的在线、付费、PvE/PvP 对照；会话可见数据口径追溯、SQL/报告迭代和结论纠正。
- **Claude Code**：一段会话将混合 Git 与历史会话输入压缩为严格 JSON 待办；另一段为 App Store 非游戏应用按 `build`、`cost`、`reach` 三个独立维度评分。
- **Codex Desktop**：当日可读记录只有上一轮经验沉淀自动化，不重复提炼。

## 关键经验

### 复杂分析先验证比较对象，结果才有解释力

KVK 分析没有直接接受“开放 10 天”的自然语言时间窗，而是反查赛季 ID、落地事件、服务器范围与 28 天周期，最终把当前和历史窗口对齐到同一星期结构。过程中发现地图/人群拆分和 KVK 付费定义会显著改变结论，随后修正了先前“付费持平”“PvP 下降 35%”等不准确表述。

**可复用做法：**在跑主查询前列出并验证 `cohort`、时间窗、地图/服务器范围、指标定义和对照组；输出时区分原始变化与相对对照组的额外变化。对事件重叠、异常峰值和尚未证实的原因只作假设，不写成归因结论。

### 结构化输出应把约束变成可验收契约

待办提取明确限定 JSON 数组、字段类型、长度和“宁缺毋滥”，因此输出可直接被后续程序消费。产品评估则用独立评分锚点避免“技术容易”掩盖成本或获客短板，并要求理由明确指出最致命的维度。

**可复用做法：**先定义 JSON schema、枚举值、数量上限和拒答条件；对多指标判断规定相互独立的量尺，并要求每条结论指出限制因素。待办任务仍应结合后续状态证据过滤已完成项，不能仅依据历史请求文本。

## 行动清单

1. 数据分析模板增加“口径确认表”和“主结论复算”步骤；口径变化后强制重新计算并显式更正旧结论。
2. 对照分析同时输出目标组变化、对照组变化和差异中的差异，避免把全局趋势误判为活动影响。
3. 自动化 JSON 提取保留源会话与最后状态证据；不确定状态默认不生成待办。
4. 商业可行性评分将外部事实与评分结果分开，立项前回查平台政策、定价和竞品数据。
