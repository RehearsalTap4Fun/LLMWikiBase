# hiring — 简历分析与面试评估模块

配合项目 skill `/resume-analysis` 使用（定义见 `.claude/skills/resume-analysis/`）。

## 招聘通道与评价口径

- **社招**：沿用现有**五维**模型；简历阶段可以形成待面试验证的假设评分，面试后再修订结论。
- **校园人才通道（校招/实习、应届、管培生、毕业生）**：使用潜力**四维**模型。简历阶段只记录信号、证据、培养项和“未验证”项，正式评分只在面试后进行；招聘类型不明确时，先向用户确认再分析。
- “未验证”表示缺少证据，不是 0/1 分，也不作为低分参与排序。仅有可培养缺口不能独立构成拒绝；强自驱须有超出课程、毕设、岗位或被分配任务最低要求的主动行动证据。
- 面试不要求候选人预先体验指定游戏，也不要求准备面试工作样本；仅凭缺乏证据而形成的拒绝应标为“建议复议”。面试前仅已确认的重大失实可终止流程，且须经用户确认。

## 工作流

```
社招面试前：读取简历 → 五维分析 → 候选人假设评分 → 生成 30 分钟在线面试计划（问题 + 追问方向）
校园人才通道面试前：读取简历 → 四维信号、证据与“未验证”记录 → 生成验证重点；不得在面试前拒绝，已确认重大失实且经用户确认除外
面试后：读取面试记录 → 核对假设、修订评分或正式四维评分 → 面试评估报告与录用建议
社招批量：同岗位多人逐个分析 → 候选人总览对比 → 用户勾选通过/拒绝 → 按勾选生成筛选备注意见（可粘贴 ATS）→ 通过者出面试计划
校园人才通道批量：比较证据覆盖与行动结论 → 用户选择推进面试/补充材料或补充面试/建议复议；不得提供面试前拒绝，已确认重大失实且经用户确认除外
```

## 目录约定

每位候选人一个目录：`candidates/<YYYY-MM-DD>-<姓名>-<岗位>/`

| 文件 | 内容 |
|------|------|
| `00-岗位要求.md` | JD / 岗位核心要求 |
| `<简历原件>` | PDF/Word/图片/文本 |
| `01-简历分析报告.md` | 社招：结构化信息、五维分析、假设评分；校园人才通道：四维信号、证据、未验证项、培养项 |
| `02-面试计划.md` | 30 分钟在线面试议程、问题与追问链、疑点清单 |
| `03-面试记录.md` | 面试笔记/转写原文（不加工） |
| `04-面试评估报告.md` | 假设核对、社招修订评分或校园人才通道正式四维评分、最终建议 |
| `05-筛选意见.md` | 社招：用户勾选的通过/拒绝 + 备注意见；校园人才通道：推进/补充验证/建议复议 |

批量筛选的横向对比文件：`candidates/<日期>-<岗位>-候选人总览.md`。

## 用法

在本仓库任意会话中：
- `/resume-analysis` 后跟简历路径或直接粘贴简历文本；
- 或自然语言："分析一下这份简历""给 X 出面试题""这是 X 的面试记录，帮我评估"。

流程可从任意阶段进入——skill 会根据候选人目录中已有的编号文件判断做到了哪一步。

## 隐私

`candidates/` 下全部内容含候选人个人信息，已在 `.gitignore` 中排除，**仅本地保留，不入库不推送**。评分标准与题库（skill 目录内）不含个人信息，正常入库。
