# 简历分析与面试评估

覆盖"简历进 → 录用建议出"的完整招聘评估流程，分面试前（阶段 1–4）和面试后（阶段 5–6）两段。

## 前置准备

1. 读取 JD、岗位名称和用户描述，先判定招聘通道。
2. 若明确为校招、实习、应届、管培生或毕业生，读取 `references/campus-intern-rubric.md`；若明确为社招，读取 `references/scoring-rubric.md`。
3. 若招聘通道不明确，只询问一次后再继续；绝不猜测，也绝不混用两套模型。
4. 确认候选人目录：`hiring/candidates/<YYYY-MM-DD>-<姓名>-<岗位>/`（日期为简历分析日）。目录已存在则说明是继续之前的流程——先看目录里已有哪些编号文件，从缺失的阶段接着做，不要重复生成。
5. 若用户提供了 JD / 岗位要求，保存为目录下的 `00-岗位要求.md`；没有则询问岗位名称与核心要求。社招至少要知道岗位方向，否则“专业匹配”维度无法评估；校招/实习也用 JD 校准潜力信号和培养项。

**隐私约束**：候选人材料含个人信息，仅存放在 `hiring/candidates/`（已 gitignore，不入库不推送）。不要把候选人姓名、联系方式写入本目录以外的任何文件。

## 阶段 1：读取简历

输入：简历文件（PDF/Word/Markdown/图片）或用户粘贴的文本。

1. 将简历原件复制（或保存粘贴内容）到候选人目录。
2. 提取结构化信息：基本信息、教育背景、工作经历时间线、项目经历、技能清单、可量化的成果数字。
3. 标记疑点：时间断档、频繁跳槽、职责描述含糊（只有"参与/负责"没有具体动作和结果）、成果无法量化、前后矛盾。疑点不是扣分项，是面试待验证项。

## 阶段 2：多维度分析

**社招**：按 `references/scoring-rubric.md` 的五个维度逐一分析，其中**主动性、投入度、学习能力**为必含维度。

**校招/实习**：按 `references/campus-intern-rubric.md` 记录四个维度的**信号、证据和验证状态**。无证据时写“未验证”，而非猜测为低分；课程、毕设和被分配的实习任务可作为实践证据，但不能自动证明自驱。不得在简历阶段输出加权总分或最终淘汰结论。

每个维度的分析必须包含：
- **证据**：引用简历原文（可截断），不允许无引用的判断。
- **证据强度**：强 / 中 / 弱。简历只能提供间接证据，写不出证据的维度标"弱"，不猜测。
- **待验证假设**：该维度上需要面试确认的具体疑问。

社招中证据弱或分数低的维度，自动成为阶段 4 面试问题的优先覆盖对象；校招/实习中证据弱或“未验证”的维度，以及培养项，自动成为优先验证对象。

## 阶段 3：候选人评分

**社招**：

1. 每个维度按锚点打 1–5 分，附一句话理由。
2. 按权重计算加权总分，对照推荐档位（见 rubric）。
3. 任一维度 ≤2 分时单独标注“单项风险”，不被总分平均掉。
4. 明确声明：这是**简历阶段假设分**，面试后在阶段 6 修订。

**校招/实习**：不评分、不计算加权总分、不按简历缺失证据作“不通过”。输出“潜力信号与证据 / 培养项 / 待验证项 / 简历筛选建议”，筛选建议仅用于决定验证重点；正式四维加权评分只在面试后进行。

产出：`01-简历分析报告.md`（模板见 `references/templates.md`），包含阶段 1–3 全部内容。

## 阶段 4：面试计划（30 分钟，在线视频面试）

面试默认全部在线（视频会议）进行。读取 `references/interview-guide.md`，生成时间盒化的面试计划：

1. 按指南的 30 分钟结构分配时段。
2. 从题库选择或改写 3–4 个行为面试问题。社招优先覆盖：证据“弱”的维度 > 分数低的维度 > 简历疑点；校招/实习优先覆盖：未验证的潜力信号与自发性来源 > 培养项 > 简历疑点。每题绑定具体的简历内容（问“你简历里 X 项目…”而不是通用问题）。
3. 每题附：考察维度、3 层追问链、评估要点（好答案/差答案特征）、防背稿追问。
4. 附疑点核实清单（时间断档、跳槽动机等，用于快问快答时段）。
5. 面试采用**纯问答形式**，不安排屏幕共享、演示等展示环节。原需当场核验的材料（创作者后台、游戏进度、Demo）用两条腿替代：口头细节追问（防背稿），以及请候选人当场报出可公开检索的账号名/链接、面试后自行核对；按指南"在线面试要点"附设备确认与防读稿/防 AI 代答观察项。

产出：`02-面试计划.md`。到此面试前流程结束，等待用户面试后提供记录。

## 阶段 5：读取面试记录

输入：面试笔记、录音转写或用户口述回忆。保存为 `03-面试记录.md`（原样保留，不加工）。

若记录过于简略（某些计划中的问题没有对应回答信息），列出缺口并询问用户补充，而不是靠想象填补。

## 阶段 6：面试结果分析

1. 社招把面试记录中的回答逐条映射到五个维度；校招/实习映射到可训练性、逻辑思维、热情与自驱、基础态度四个维度。均引用候选人的实际回答作为证据。
2. 逐一核对阶段 2 的待验证假设：已证实 / 已证伪 / 仍不确定。
3. 社招修订评分：给出每个维度“简历分 → 面试后分”及变化原因；重算加权总分与推荐档位。校招/实习在此时才按 `campus-intern-rubric.md` 的四维权重正式评分，并给出行动结论。
4. 汇总亮点与红旗（red flags）。红旗须区分“硬红旗”（诚信问题、经历造假嫌疑）与“软红旗”（表达弱、准备不足）。定性规则：
   - **资格与事实类条目失实**（证书、学历、任职等可验证信息与事实不符）一律记硬红旗；成因解释（如"简历由 AI 生成未校对"）不改变定性——简历由本人提交即对内容负责。硬红旗不被总分平均，在结论中单独处理（参照 rubric 单项风险规则）。
   - **"坦诚"仅指主动披露**。被追问后才承认的失实/收窄属被动应答，最多记为"应答不防御"的弱信号，不得列为亮点、不得用于抵消红旗。
   - **过程叙述流畅 ≠ 能力已验证**：能讲清方法/流程只证明参与过，不证明成果因果归属或独立能力；能力结论必须有场景题/实操类的直接验证支撑，否则在报告中标注"未经直接验证"。
5. 社招给出最终建议：强烈推荐 / 推荐 / 待定 / 不推荐，以及后续动作（进入下轮、加面验证某维度、背调重点、婉拒）。校招/实习遵守 campus/intern rubric：已确认的重大失实是独立否决；其余“不通过”须有面试证据并由用户确认，否则结论为“建议复议”。

产出：`04-面试评估报告.md`。

## 批量筛选模式（同岗位多候选人）

同一岗位有多位候选人时，逐人完成阶段 1–3 后进入本模式。不得将社招和校招/实习放入同一评分模型或总分排序：

1. **总览对比**：产出 `hiring/candidates/<日期>-<岗位>-候选人总览.md`。社招包含评分总表（按总分排序）、一句话画像与核心疑点、横向结构观察、推进建议；逐维度对比而不只比总分，总分差 <0.3 视为同档，用维度结构和风险点区分。校招/实习比较证据覆盖、潜力信号、培养项和待验证项，不用简历阶段总分排序；“未验证”是缺少证据，不是 0 分或低分，不能排在已观察到的低分之后。
2. **筛选决策（勾选）**：
   - **社招**：用 AskUserQuestion 向用户逐人提供“通过 / 拒绝”勾选，每题一位候选人，题干附总分与档位，选项描述附一句话画像/关键疑点作参考。只提供决策依据，不代替用户做决定；用户可通过 Other 附加说明（如“待定，先看下一批”）。
   - **校招/实习**：在阶段 1–3 后，校招/实习候选人只能选择“推进面试 / 补充材料或补充面试 / 建议复议”；题干附信号覆盖和待验证重点。面试前不得提供“拒绝”或终止流程选项。唯一例外是已确认的重大失实：记录可核验事实后，经用户确认，可在面试前终止。
3. **备注意见**：按勾选结果为每位候选人生成 `05-筛选意见.md`（模板 D）：
   - **社招**：**通过**时写推进理由 2–3 条（引用简历证据）+ 面试重点关注项；**拒绝**时写核心理由（基于岗位匹配证据，客观陈述缺口，不写推测性或与岗位无关的负面表述）+ 后续建议（转其他岗位 / 入人才库 / 婉拒）。措辞可直接粘贴到 ATS（如 Moka）筛选评语栏。
   - **校招/实习**：记录推进或补充验证的依据、培养项和待验证项；“建议复议”须说明缺少何种面试证据。不得生成“不通过”或拒绝意见，除非已确认重大失实并有用户确认。
   同时把决策结果同步进总览文件（社招评分总表新增“筛选决策”列；校招/实习总览记录面试前动作）。
4. 社招“通过”者继续阶段 4 生成面试计划；社招“拒绝”者流程到此终止。校招/实习的“推进面试”和“补充材料或补充面试”继续验证流程；“建议复议”保留给用户决定，不终止候选人流程。

## 使用原则

- **证据优先**：所有判断都要能指回简历原文或面试记录原话。
- **假设与结论分离**：面试前的一切评价都是待验证假设，报告中明确标注。
- **不做无依据的负面推断**：跳槽频繁、有断档只是待核实信号，动机问清楚之前不定性。
- **对比多位候选人时**：逐维度横向对比，而不是只比总分。
