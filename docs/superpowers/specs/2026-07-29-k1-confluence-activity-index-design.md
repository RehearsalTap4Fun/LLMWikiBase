# K1 Confluence 活动本地索引设计

日期：2026-07-29  
状态：已获用户确认

## 1. 背景

K1 项目活动知识集中在 Confluence 的 `K1活动` 页面树：

- 根页面：`K1活动`
- pageId：`73598402`
- URL：<https://wiki.tap4fun.com/pages/viewpage.action?pageId=73598402>
- 当前已验证一级子页面数量：62
- 一级活动下还存在通行证、商店、兑换、排行和玩法等多级子页面

现有本地页面 `k1-project-knowledge-map` 和 `k1-confluence-routing` 只能把查询路由到 Confluence 的大分支，不能稳定完成“活动名、别名或玩法机制 → 具体活动主题 → 相关 Wiki 子页面”的精确定位。

## 2. 目标

建立一套轻量、可重复同步的本地活动索引，使 Codex 在用户提到 K1 活动时能够：

1. 通过活动名、旧标题、别名、子页面标题、机制标签和主题摘要定位活动。
2. 定位到具体活动主题及最相关的 Confluence 子页面。
3. 对规则、时间、服务器范围、奖励和道具 ID 等具体问题实时回源读取 Wiki。
4. 在不保存 Wiki 全文的前提下，保留足够的本地语义信息用于可靠路由。
5. 通过重复执行同步命令发现新增、改名、移动、更新、删除或无权限页面。

## 3. 非目标

- 不把 Confluence 页面全文复制到本地。
- 不把奖励表、服务器范围、活动档期、道具 ID 等易变信息沉淀为长期事实。
- 不判断某个活动当前是否正在开放；Confluence 的 `current` 仅代表页面发布状态。
- 不替代 Confluence 作为活动规则的最终事实来源。
- 不修改 `sources/` 目录。
- 不在本阶段建设通用 RAG、向量数据库或 SQLite 检索系统。

## 4. 收录边界与粒度

### 4.1 收录范围

全量遍历 `K1活动` 根页下所有当前凭证可读的后代页面。标题包含“旧”“过期”“废弃”“需删除”的页面仍保留在索引中，但必须打历史或废弃状态标签，不能作为当前规则直接回答。

### 4.2 本地页面粒度

每个一级活动主题建立一份 Markdown 页面。该主题下的二级及更深页面不单独创建 Markdown 文件，而是作为主题页内的结构化索引条目。

这使本地文件数量大致与一级活动数量一致，同时仍能直接路由到“通行证”“商店”“兑换”等具体子页。

## 5. 文件结构

### 5.1 新增文件

- `wiki/work/k1-activity-catalog.md`：全部一级活动的主目录。
- `wiki/work/k1-activities/k1-activity-<pageId>.md`：活动主题页，使用稳定 pageId 作为文件名。
- `tools/sync_k1_activity_index.py`：递归发现与增量同步工具。
- `tools/search_k1_activity.py`：只读本地索引的活动查询工具。
- `.cache/k1-activity-index/state.json`：页面版本、父子关系、旧标题和同步状态；不包含正文。
- `tests/test_k1_activity_index.py`：同步、生成、查询和异常行为测试。
- `tests/fixtures/k1_activity_index/`：脱敏合成测试数据，不保存真实 Wiki 正文。

### 5.2 修改文件

- `AGENTS.md`：增加 K1 活动查询路由规则。
- `wiki/index.md`：只增加 `k1-activity-catalog` 一条入口。
- `wiki/work/k1-confluence-routing.md`：与活动目录双向链接，并更新“本地无法访问”这一过期限制。
- `wiki/log.md`：实施完成后按知识库约定记录本次 ingest。
- `.gitignore`：忽略 `.cache/k1-activity-index/`。

`wiki/work/` 当前因包含公司内部信息而被 Git 忽略；活动索引继续遵循该安全边界。设计文档和工具代码可以提交，内部活动页面不提交公开仓库。

## 6. 活动主题页数据模型

### 6.1 Frontmatter

活动主题页遵守知识库六字段规范：

```yaml
---
title: K1 绯夜假面
type: source-summary
domain: work
source: "https://wiki.tap4fun.com/pages/viewpage.action?pageId=248877776"
date: 2026-07-29
confidence: medium
tags: [K1, 活动, 绯夜假面, 节日活动, 收集, 通行证, 商店]
links: ["[[k1-activity-catalog]]", "[[k1-confluence-routing]]"]
---
```

单一 Confluence 页面树可以证明页面内容和结构，但不足以把综合判断标为 `high`。首次生成统一使用 `medium`；内容模糊、过期或只能从标题推断时使用 `low`。

### 6.2 正文结构

每个主题页包含：

1. 一句话主题摘要。
2. 活动别名、旧标题和常见简称。
3. 标签分组：
   - 机制：通行证、兑换商店、转盘、排行、充值、收集、小游戏、PVP、PVE 等。
   - 场景：节日、新服、回归、KVK、日常等。
   - 页面状态：Wiki 当前、历史、过期、废弃、不可访问、待复核。
4. 主题根页面元数据：pageId、URL、版本、Wiki 更新时间、最近同步时间。
5. 子页面表格：层级路径、标题、用途、pageId、版本、Wiki 更新时间、URL、单句摘要和复核状态。
6. “回源边界”：提醒具体数值、开放时间和奖励必须读取最新 Wiki。

若当前 CLI 无法提供 Wiki 更新时间，该字段明确写为“未知”，并保留版本号与本地同步时间，不进行推断。

## 7. 总目录数据模型

`k1-activity-catalog.md` 每个一级活动一行，字段包括：

- 活动标题与别名
- 本地主题页 wikilink
- 一句话主题摘要
- 核心机制标签
- 页面状态
- 后代页面数量
- 主题根 Wiki URL
- 最近同步时间

目录按当前可用、历史/过期、不可访问三个状态区块展示。标签本身仍保留在各主题页 frontmatter 中，便于 `rg`、Obsidian 和本地查询工具共同使用。

## 8. 自动生成区与人工维护区

同步工具必须区分两类内容：

- 自动生成区：页面树、pageId、URL、版本、更新时间、同步时间和后代数量。
- 人工维护区：主题摘要、别名补充、语义标签、关联本地知识页和人工备注。

同步不得覆盖人工维护区。页面新增或版本变化时，工具可以基于标题和正文临时生成候选摘要和标签，但必须标记 `待复核`。初始导入由 Codex 读取实时正文并完成第一轮语义整理；后续同步自动刷新事实元数据，并把需要重新审阅的页面集中报告出来。

## 9. 同步流程

### 9.1 凭证解析

工具通过现有 Confluence CLI `%USERPROFILE%\.skills\confluence\scripts\confluence.pyz` 访问 Wiki，不自行实现或复制认证逻辑。可以用 `--confluence-cli` 显式覆盖路径，代码和文档中不得固化具体用户名。

凭证读取顺序：

1. 当前进程环境变量。
2. Windows 用户环境变量 `HKCU\Environment`。

使用的变量为 `CONFLUENCE_URL`、`CONFLUENCE_EMAIL` 和 `CONFLUENCE_API_TOKEN`。工具只能报告变量是否存在，不得打印或保存其值。

### 9.2 全量发现

1. 调用 `check` 验证连接。
2. 从 pageId `73598402` 开始广度优先遍历。
3. 对每个页面调用 `page children` 获取直接子页面。
4. 比较 API 返回的 `total` 与实际结果数量；若不一致则终止同步。
5. 构造完整的 pageId、父 pageId、层级路径和一级主题归属关系。

`page children` 使用足够大的 limit；若服务端仍截断且 CLI 不支持分页，工具必须失败并保留旧索引，不能把截断结果当作完整树。

标准同步命令为 `python tools/sync_k1_activity_index.py --root-page-id 73598402`。命令完成页面发现、增量元数据刷新和待复核报告；人工维护区的语义复核仍由 Codex 在同一任务中完成。

### 9.3 增量内容读取

1. 将发现结果与 state 中的 pageId 和版本比较。
2. 只对新增或版本变化的页面调用 `page get --format plain`。
3. 使用 UTF-8 输出，避免 Windows GBK 无法编码特殊空格等字符。
4. 正文只在当前进程内用于摘要和标签候选，不写入 state、缓存、日志或测试 fixture。

### 9.4 变更合并

- 改名：更新展示标题，将旧标题加入别名。
- 移动：更新层级路径和一级主题归属。
- 新增：加入主题页并标记待复核。
- 版本变化：刷新元数据并标记相关摘要待复核，保留现有人工摘要。
- 从页面树消失：保留原记录并标记 `missing-from-root`，不自动删除；该状态可能表示删除、移出分支或权限变化。
- 正文读取明确返回 403/404：保留原记录并标记不可访问，不自动删除。
- 一级主题被移除：保留主题页并移入历史/不可访问区。

### 9.5 原子写入

所有输出先写入同目录临时文件。只有认证、遍历、数量校验、结构校验和 Markdown 生成全部成功后，才原子替换目标文件并更新 state。任何部分失败都不得修改旧索引。

## 10. 查询路由

### 10.1 匹配优先级

`tools/search_k1_activity.py` 按以下顺序匹配：

1. 一级活动标题精确匹配。
2. 活动别名或旧标题精确匹配。
3. 子页面标题精确匹配。
4. 标题或别名部分匹配。
5. 多个机制/场景标签联合匹配。
6. 主题摘要与子页面摘要全文匹配。

中文全角/半角标点、空白、英文大小写和常见 `K1` 前缀在匹配前归一化。分数接近或同分时返回多个候选，不自动猜测。

### 10.2 Codex 查询流程

`AGENTS.md` 增加以下行为：

1. 用户提到 K1 活动时，先运行本地活动查询工具。
2. 读取命中的本地主题页，确认主题、别名、标签和子页路径。
3. 根据问题意图选择最相关的 Wiki 页面：
   - 总体规则读取主题根页。
   - 通行证、商店、兑换、排行等读取对应子页。
   - 时间、服务器范围、奖励、道具 ID 等易变信息必须实时回源。
4. 多个候选时向用户列出候选或读取最高相关的少量页面后说明判断依据。
5. 回答引用本地主题页和实际读取的 Confluence URL。
6. 本地无命中时执行 Confluence 搜索，并把新页面纳入下次同步候选。

本地摘要只负责路由，实时 Wiki 页面是具体活动规则的事实来源。

## 11. 错误处理与安全

- 认证失败：只报告缺失变量或连接错误，不修改文件。
- 页面树枚举失败，或单页读取发生网络、服务端、解析等非 403/404 错误：整次索引写入失败；旧索引继续可用。
- 单页正文明确返回 403/404：允许同步继续，保留旧摘要并标记不可访问。
- 页面数截断：整次失败，不把缺页解释为删除。
- JSON 或正文编码异常：记录 pageId 和错误类型，不记录正文。
- Markdown 校验失败：不替换旧文件。
- 页面暂时不可访问：保留旧索引并标记状态。
- Token、邮箱和认证请求头不得出现在标准输出、日志、state 或测试数据中。
- 真实 Wiki 全文不得写入仓库；测试只使用自行构造的短文本。

## 12. 验证与验收

### 12.1 自动测试

- 递归遍历正确保留父子关系和一级主题归属。
- API `total` 与结果数量不一致时拒绝写入。
- 新增、改名、移动、版本变化、删除和无权限场景符合设计。
- 原子写入失败后旧文件保持不变。
- 同步不覆盖人工摘要、标签、互链和备注。
- state 不包含正文或凭证。
- 每个生成 Markdown 页面具备六个必填 frontmatter 字段。
- 所有活动文件名全库唯一，source URL 的 pageId 与记录一致。
- 每个子页面恰好归属一个一级主题。
- `search_k1_activity.py` 的匹配优先级和歧义返回稳定。

### 12.2 初始数据验收

- 当前根页能够发现 62 个一级主题；最终数量以同步当次 API 完整结果为准。
- `绯夜假面` 能定位到主题页。
- `绯夜通行证` 能直接定位到对应 Wiki 子页。
- `绯夜 + 商店` 能定位到绯夜宝铺或相关兑换页面。
- 历史活动、旧标题和页面改名能够通过别名找到。
- 本地索引不包含 Wiki 完整正文、奖励明细或凭证。
- `wiki/index.md`、`k1-activity-catalog`、主题页和 `k1-confluence-routing` 之间链接闭环。
- 对生成和修改的 wiki 页面执行可用的 lint；当前仓库若仍缺少 AGENTS.md 中提到的 `tools/lint.py`，则由同步工具完成同等范围的结构校验并明确记录该环境差异。

## 13. 实施顺序

1. 实现 Confluence CLI 包装、凭证解析和只读树遍历。
2. 实现 state、完整性检查和增量变更模型。
3. 实现主题页与总目录生成，并保护人工维护区。
4. 实现本地查询工具。
5. 增加自动测试和脱敏 fixture。
6. 对 `K1活动` 执行初始全量同步并完成第一轮摘要、别名和标签复核。
7. 更新 `AGENTS.md`、`wiki/index.md`、`k1-confluence-routing.md` 和 `wiki/log.md`。
8. 运行结构检查与代表性查询验收。

## 14. 设计决策摘要

- 采用 Markdown 主题页，而不是单一超大目录或数据库。
- 一级活动一页，后代页面作为主题页内条目。
- 文件名使用 pageId 保持稳定。
- 本地只存路由信息，不存 Wiki 全文。
- 元数据自动同步，语义摘要和标签受保护并对变化标记待复核。
- 查询命中后实时读取最相关 Wiki 页面。
- 旧、过期和不可访问内容保留但明确降级，不静默删除。
