# 校招/实习简历分析分支优化设计

## 背景与目标

现有 `resume-analysis` 使用通用五维模型，适合社招，但会把当前专业知识和岗位经验放在较高权重。首批 27 届实习生面试复盘表明，校招/实习应从“筛成品”切换为“筛潜力”：统一考察可训练性、逻辑、热情与自驱、基础态度，并把诚信作为独立红线。

本次仅优化校招/实习分支。社招继续使用现有五维模型，历史候选人文件不迁移，现有产出文件名保持不变。

## 适用范围与路由

当 JD、岗位名或用户描述明确包含“校招、实习、应届、管培生、毕业生”等标记时，启用校招/实习四维模型。明确为社招时继续使用现有五维模型。招聘类型不明确时询问用户一次，不自行猜测。

主技能负责识别招聘类型并路由。新增 `references/campus-intern-rubric.md` 承载校招/实习专用规则；现有 `references/scoring-rubric.md` 保持为社招/通用量规。`references/interview-guide.md` 和 `references/templates.md` 增加按招聘类型选择的校招/实习章节。`hiring/README.md` 补充两种模型的说明。

## 校招/实习评估模型

采用“淘汰线 + 四维评分”的双层模型。

| 维度 | 权重 | 核心证据 |
|------|------|----------|
| 学习潜力 / 可训练性 | 30% | 获得新框架或角度后能否快速跟上、迁移和修正 |
| 逻辑思维 | 25% | 是否能在熟悉领域建立结构、因果链与边界判断 |
| 热情与自驱 | 35% | 是否存在持续、自愿、有成本的行动和实际产出 |
| 基础态度 | 10% | 是否愿意深入思考、沉下心处理细节并对事实负责 |

诚信不参与加权。简历关键信息失实经核实后，一票否决。

其他淘汰线包括：点拨后仍完全无法形成基本推理、明确缺乏相关热情且没有任何自发动手信号、给出角度后仍拒绝深入思考、沟通完全无法完成。它们只能依据面试事实成立，并须由用户确认。简历阶段只能列为待验证项。

游戏拆解不深、缺少 SLG/商业化/付费经验、不熟悉引擎或策划工具、付费较少、偏好其他游戏品类均属于培养项。培养项不得单独导致淘汰，也不得被包装成潜力不足；它们只进入面试验证或入职培养清单。

## 简历阶段

简历阶段提取四维相关的潜力信号、证据强度和待验证项，不计算最终总分。逻辑或可训练性没有可靠证据时标记“未验证”，不得默认打低分。

独立项目、课程项目和实习经历必须区分“完成要求”与“自发超额行动”。只有候选人拥有选择空间，并能证明至少一项超出学业或岗位硬性要求的主动行为，才可计为强自驱信号。可用证据包括自行选题、额外迭代、主动解决未被要求的问题、课程或实习结束后继续维护，以及可核查的实际产出。

仅完成课程作业、毕业设计或实习分配任务，只记为实践经历，不直接提高热情与自驱评分。

一旦出现可追溯的强自驱/动手信号，默认建议推进面试。该保护机制不能抵消诚信等淘汰线。

## 面试设计

校招/实习面试保持 30 分钟在线视频纯问答。不得提前要求候选人试玩指定游戏，也不得要求准备面试作品。所有判断基于候选人已有经历和现场问答；未准备指定材料不能成为负面信号。

面试题必须覆盖以下证据链：

1. 自发性：这是硬性任务还是自主选择；最低要求是什么；候选人做了哪些额外工作；如果没有本人推动，什么不会发生；结束后是否继续迭代。
2. 逻辑与可训练性：先让候选人分析自己熟悉的游戏、项目或领域，再由面试官给出一个新框架或角度，观察其能否建立因果链并迁移。
3. 学习潜力：最近一次进入陌生领域的学习路径、时间标尺、验证方法和实际产出。
4. 态度与诚信：用具体事实、细节和可核查口径验证，不以笼统印象定性。

判定逻辑或可训练性不足前，必须记录“初始回答 → 面试官给出的具体框架/角度 → 点拨后的推理变化 → 可训练性结论”。若未完成该测试，不得以“分析浅、追问答不出、逻辑不足”作淘汰依据，只能标为证据不足并安排补充验证。

不得用游戏时长、付费金额、是否玩 SLG、是否主动提攻略推断热情。口头声称“热爱游戏”也不是强证据；热情只由持续、自愿且有成本的行动支撑。

## 面试后评分与结论

完成面试后再正式给四维 1–5 分和加权总分。评估报告强制包含：

1. 命中的淘汰线及事实证据；
2. 观察到的潜力、自驱与动手信号；
3. 是否进行过点拨，以及点拨前后的反应；
4. 仅需培养的知识或经验缺口。

行动结论分为“强烈推荐推进 / 推荐推进 / 证据不足，需补充面试 / 不通过”。若“不通过”没有命中有证据的淘汰线，必须改为“建议复议”。即使最终不通过，也要记录正向潜力与动手信号，便于横向比较和复议。

## 文件与兼容性

保持现有候选人目录和编号文件不变：

- `01-简历分析报告.md`：校招/实习版本不输出最终总分，改为潜力信号、证据强度与待验证项。
- `02-面试计划.md`：增加自发性追问链、熟悉领域逻辑题和强制点拨测试。
- `04-面试评估报告.md`：增加四维正式评分、淘汰线、点拨记录、培养项和复议检查。
- 批量总览与 `05-筛选意见.md`：校招/实习候选人按行动结论比较，不把“未验证”当低分。

社招文件结构和五维量规保持原状。

## 失败与边界处理

- 招聘类型不明确：先询问，不混用两套模型。
- 面试记录缺少点拨测试：逻辑和可训练性标为证据不足，不能据此淘汰。
- 自发性来源不明：按普通实践经历处理，生成追问，不授予强自驱信号。
- 只有培养项缺口：不得输出不通过；按其他潜力证据决定推进或补面。
- 诚信疑点尚未核实：标为待核实硬红旗，不提前定性为造假。
- 评价只有笼统印象：要求补充具体事实，否则该结论无效。

## 验证方案

使用匿名虚构材料做前后对照，至少覆盖：

1. 有真实自发项目但缺少 SLG/商业化经验，应推进而非被培养项误杀；
2. 只有课程作业或被分配的实习任务，可记实践但不能自动判强自驱；
3. 初始分析较浅、获得框架后明显进步，应体现可训练性；
4. 项目亮眼但关键信息经核实失实，诚信红线仍优先；
5. 明确社招案例仍使用原五维模型。

先由独立测试代理在未加载新版规则时运行基线案例并保留原始输出，归纳实际失败模式；再做最小技能修改，用相同案例复测。最后运行技能结构校验、规则检索检查和仓库差异检查。测试材料与结果不得包含真实候选人个人信息。

## 完成标准

- 校招/实习与社招能稳定路由到各自模型；
- 简历阶段不因缺少不可观察证据而打低分；
- 培养项不会单独产生淘汰结论；
- 强自驱信号必须区分自发行动与完成要求；
- 逻辑或可训练性负面判断包含点拨前后证据；
- 无淘汰线证据的拒绝会转为建议复议；
- 社招现有流程和文件命名保持兼容；
- 技能结构校验和匿名回归场景通过。
